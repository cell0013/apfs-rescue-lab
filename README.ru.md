# APFS Rescue Lab

**Бесплатный open-source проект для диагностики и исследования восстановления APFS.** Донаты только по желанию: [поддержать на Buy Me a Coffee](https://buymeacoffee.com/apfs.rescue.lab).

> **Используйте исключительно на свой страх и риск.** Программа предоставляется **«КАК ЕСТЬ»**, без каких-либо гарантий сохранности данных, успешного восстановления, загрузки системы или пригодности для какой-либо цели. Сначала сделайте резервную копию; работайте только с независимыми копиями. См. [DISCLAIMER.md](DISCLAIMER.md) и [LICENSE](LICENSE).

## Зачем создан проект

При восстановлении виртуальной машины с macOS Catalina возникло повреждение метаданных APFS. Готовое и проверенное решение **именно для этого случая** найти не удалось; доступная в интернете информация не помогла в достаточной степени. На исследование Object Map, checkpoint, повторные проверки и эксперименты с ИИ ушло **несколько суток**.

Мы решили опубликовать код и инструкцию, чтобы другим людям не приходилось повторять те же исследования с нуля. **Это не утверждение, что других продуктов восстановления APFS не существует.** Успех одного эксперимента не гарантирует успеха на другом диске.

## Первая версия v0.1

- **APFS Analyzer** — читает GPT, APFS-суперблок и контрольные точки.
- **Block Diff** — сравнивает два RAW-образа поблочно.
- [Анонимизированный разбор случая](docs/recovery-case.md).

**Режим экспериментального восстановления уже опубликован:** [checkpoint selector](docs/experimental-checkpoint.md). Он создаёт клон RAW и делает неактивными более новые checkpoint. В нашем случае предыдущая программа **сама подобрала** проверяемый XID; опубликованная версия пока принимает его как параметр и ещё не объединяет оба этапа в один автоматический процесс. Именно такой метод участвовал в успешном эксперименте, но **он не является полноценным откатом или гарантированно безопасным восстановлением APFS**. Оригинал никогда не изменяем.

## Давайте развивать проект вместе

**Мы очень ждём ваши дополнения, замечания, предложения и реальные истории использования.** Фотографии семьи, документы, результаты многолетней работы и исходный код зачастую невозможно восстановить из других источников. **Данные — одна из самых ценных вещей, которые у нас есть.** Мы хотим вместе с сообществом создать бесплатный и надёжный инструмент, способный помочь большему числу людей.

- **Идея, пожелание или запрос совместимости:** [создать Issue](https://github.com/cell0013/apfs-rescue-lab/issues/new).
- **Исправления кода, тесты, переводы и документация:** [отправить Pull Request](https://github.com/cell0013/apfs-rescue-lab/pulls), см. [CONTRIBUTING.md](CONTRIBUTING.md).

**Нам важны и успешные, и неудачные истории:** они помогут найти ограничения и не допустить потери данных у других пользователей.

**Конфиденциальность:** GitHub Issues публичны. Не прикладывайте RAW/VMDK, личные файлы и журналы без очистки, реальные имена пользователей, полные пути, UUID томов, серийные номера, пароли, ключи или токены. Лучше обезличенное описание и искусственный тестовый образ.

## Автоматический поиск checkpoint (экспериментальный)

В нашем случае **не пришлось вручную выбирать XID**: предыдущий анализатор сам предложил подходящий checkpoint. Теперь эти действия объединены:

```bash
python3 apfs_rescue.py analyze --source "/path/to/disk.raw" --report "./auto-analysis.json"
```

Создание кандидата **только в новой копии**, с подтверждением риска:

```bash
python3 apfs_rescue.py recover --source "/path/to/offline-test-source.raw" \
  --output "/path/to/new-test-candidate.raw" \
  --i-understand-this-can-destroy-data
```

Это не гарантированный ремонт. При неоднозначности или неподходящей структуре программа должна остановиться. Опыт восстановления подтверждён только для конкретного случая Catalina, **универсальность для всех macOS и APFS не подтверждена**. См. [инструкцию и совместимость](docs/auto-recovery.md).

## Как запустить

Подробный пошаговый порядок действий: [инструкция по исследованию APFS](docs/quick-start.md).

Нужен Python 3.9+; внешние пакеты не требуются. Образы должны быть отключены от записи.

```bash
python3 tools/apfs_analyzer.py --source "/path/to/disk.raw" --out analysis.json

python3 tools/block_diff.py --source "/path/to/original.raw" \
  --compare "/path/to/trial.raw" --out-dir ./diff-report
```

На вход подаются RAW-образы целых дисков с GPT и APFS. Скрипты ничего не исправляют и не монтируют.

Никогда не публикуйте исходные образы, личные каталоги, пароли, SSH-ключи, токены или неочищенные логи. Даже сообщение `fsck_apfs` об отсутствии ошибок не гарантирует успешную загрузку Catalina.
